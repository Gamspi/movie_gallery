## Покрытые сценарии

- Чистый монитор: граница 29 999/30 000 мс, полезный прогресс, изменение диапазона, остановка ожидания, сброс между сессиями.
- Стартовый торрент-буфер: общая скорость и посторонние куски не сбрасывают интервал; готовность снимает предупреждение без ошибки и остановки.
- Просмотр: реальный loopback HTTP Range + виртуальные часы менеджера; пауза и seek перезапускают интервал, включая сохранение активного запроса при перемотке в ту же позицию.
- Независимые запросы: прогресс нужных кусков, отмена, завершение, закрытие источника, отсутствие регистрации готового диапазона.
- Хэш субтитров: оба локальных Range-запроса помечены, сервер исключает их из предупреждения. Для внешнего имени хоста заголовок отсутствует; тестовый DNS направлен на локальный MockWebServer.
- Старые callback и ViewModel не останавливают новую сессию и не сбрасывают её предупреждение. URL-плеер не получает торрент-предупреждения.
- Временная ошибка опроса havePiece не останавливает готовую сессию.

Проведено независимое ревью субагентом. Исправленный при ревью случай seek с сохранённым HTTP-запросом покрыт регрессионным тестом. git diff --check прошёл; Markdown проверен на UTF-8 без BOM и локальные ссылки.

## Ограничения

Новый интерфейс не установлен и не проверен на телефоне или ТВ в этом прогоне. Тесты не подтверждают JNI, реальные пиры, фокус/размер предупреждения и управление физическим пультом. Для приёмки нужны остановка и восстановление загрузки, пауза без предупреждения, выход к раздачам и запуск другой сессии.

До первого READY плеер сохраняет прежнее playWhenReady=false: подготовка Media3 после готовности торрент-буфера ещё не считается ожиданием воспроизведения. Стартовая торрент-буферизация и 60-секундный таймаут метаданных действуют отдельно.

В сборке остаются прежние предупреждения о delicate coroutine API StreamServer и устаревших Gradle API. Полная приёмка этапа 3 на ТВ и живом OpenSubtitles остаётся открытой.
