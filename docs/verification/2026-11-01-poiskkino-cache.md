# G-04: PoiskKino, HTTP-кэш и таймаут каталога

Дата: 2026-11-01. Проверена база `d3ee3ef` + локальные изменения G-04; реализация зафиксирована в `3cbea48`.

## Реализация и контракт

Работа разделена между субагентами: настройки/UI, клиент PoiskKino, кэш/подключение. После восстановления контекста проведено дополнительное ревью тех же областей.

[Официальный OpenAPI](https://api.poiskkino.dev/documentation-json) сверен 2026-11-01: v1.5, курсор next/hasNext для списков, page для поиска, словарь /v1.5/dictionary/genres с числовыми id. Старый план v1.4 уточнён в существующем документе. Сохранённый Kinopoisk/Tmdb остаётся выбранным, отсутствующий/неизвестный выбор становится PoiskKino.

HTTP-кэш 20 МБ общий для трёх клиентов. Списки/поиск/словари — час, карточки — сутки. Ошибки не кэшируются даже с разрешающими заголовками сервера. Ключ отделён от URL и заголовков дискового кэша, варианты изолированы отпечатком источника/ключа. Автоматические редиректы отключены, чтобы Location не вернул ключ в URL кэша. Таймаут чтения Кинопоиска — 45 секунд; остальные connect/write остаются 15 секунд.

Основной код кэша ради этого теста не менялся.
