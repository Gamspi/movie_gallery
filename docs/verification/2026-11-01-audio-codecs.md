# G-06: FFmpeg и ошибки плеера

Дата: 2026-11-01. База `e450ec8` + локальные изменения G-06; коммит не создан. [План](../superpowers/plans/2026-11-01-audio-codecs.md).

## Реализация

Работа разделена между тремя субагентами: сборка, ошибки/UI и синтетические данные/debug-проверка. Root завершил интеграцию, после чего субагенты сборки и ошибок выполнили повторное ревью.

Локальный модуль `decoder-ffmpeg` использует четыре официальных Java-класса и JNI Media3 1.11.1. Девять исходных файлов/архивов проверяются SHA256 из `decoder-ffmpeg/sources.sha256`. FFmpeg 6.0.1 собран NDK r26b (26.1.10909125), Clang 17.0.2; CMake 3.22.1. Изменён локальный рецепт CMake: JNI линкуется с отдельными shared libavcodec/libavutil/libswresample. FFmpeg-исходники не меняются. Конфигурация содержит только AAC, AC3, EAC3, DCA и TrueHD; необходимые парсеры AC3/MLP включаются зависимостями.

Проверка `scripts/verify-ffmpeg.sh` прошла: четыре ELF32 ARM-библиотеки, unversioned DT_NEEDED, нет RPATH/RUNPATH, CONFIG_GPL=0 и CONFIG_NONFREE=0. Нативные размеры до упаковки APK: avcodec 568352, avutil 406824, swresample 72352, ffmpegJNI после patch 99776 байт. В APK JNI после stripping занимает 9136 байт. Используется C без assembly-оптимизаций; нагрузка на целевом ТВ требует отдельного измерения.

Основная фабрика: системное аудио первым, FFmpeg вторым (ON), два текстовых рендерера сохранены. FFmpeg расширяет аудиоподдержку, не видео. ON не гарантирует переключение на расширение после любой ошибки уже выбранного системного декодера.

Ошибки классифицируются по структурированным Media3-кодам/MIME/HTTP-статусу; сырые исключения, URL и ключи не выводятся. Для временных сетевых ошибок доступен повтор; для ошибки аудио — другая поддерживаемая дорожка, если известны группа и неудачный выбор. Сохранённая группа позволяет восстановиться после очистки currentTracks. Ошибка хранения торрент-сессии имеет приоритет над меню аудио и не предлагает повтор старого URL.

Лицензии и рецепт замены shared-библиотек: [NOTICE](../../decoder-ffmpeg/NOTICE.md); полные тексты и ссылки включаются в APK assets/licenses.

## Автоматические проверки

Первичная конфигурация Gradle выявила запрет Provider в Android SourceSet API; исправлено явными каталогами и зависимостью preBuild от prepareFfmpeg. Затем `testDebugUnitTest -x :decoder-ffmpeg:prepareFfmpeg` на проверенных Java-исходниках: BUILD SUCCESSFUL за 4 мин 15 с; XML 46 наборов, 393 теста, 0 failures/errors/skipped. В этом прогоне native-подготовка намеренно исключена; он не доказывает JNI.

Далее новая коллекция SourceSet потребовала String вместо File; тип путей исправлен. Полный прогон с автоматической подготовкой JNI прошёл (2 мин 57 с), затем упаковка повторена с явно закреплённым NDK r26b (2 мин 4 с). Предупреждения об отсутствии инструмента stripping исчезли.

**Финальный прогон после TrueHD patch:** Docker `testDebugUnitTest assembleDebug`, BUILD SUCCESSFUL за 2 мин 3 с, 87 задач: 21 выполнена, 66 UP-TO-DATE. Подготовка FFmpeg/patch/ELF-проверка, изменённый код, unit-тесты и упаковка выполнены заново. XML: **46 наборов, 393 теста, 0 failures/errors/skipped**; на 14 тестов больше `e450ec8`. Проверены классификация/действия ошибок, очистка состояния VM, порядок реальных аудиорендереров и сохранение двух текстовых слоёв при дополнительном аудиорендерере.

APK: **34163938 байт**, SHA256 `0E00A79CF09A7C810FA2224630477D60043BE508DB9418F6B57C784234287FD9`. Измеренный прежний APK — 33293579 байт; разница +870359 байт. Промежуточный размер 48 МБ объяснялся неиспользуемыми промежутками инкрементального ZIP: субагент проверил структуру и отсутствие дублированных DEX-классов. Перед финальной упаковкой прежний сгенерированный APK перемещён в `build/codec-probe/before-truehd-fix.apk`, архив создан заново.

В APK проверены только `lib/armeabi-v7a` и все пять license/notice/patch assets. Другой ABI не добавлен.

## Устройство

Выбран пользователем Redmi Note 8 Pro, API 30, abilist `arm64-v8a,armeabi-v7a,armeabi`, Wi-Fi ADB порт 36987. Проверена база `e450ec8` + локальные изменения G-06; установлен APK с указанным выше SHA256, установка поверх прежнего приложения Success.

Шесть синтетических файлов (20 секунд, H264 + 440 Гц / 48 кГц; четыре стереокодека, дополнительно TrueHD 5.1 и смешанный MKV) созданы скриптом и загружены в каталог приложения. Генератор: FFmpeg 9.0.2, локальный image ID `sha256:f4191c1abe18d75c49a23f7224d1403d55334f80013a47cb096f5056cf19617b`; manifest с SHA256 файлов — `build/codec-probe/manifest.json`. Это генератор тестовых данных, он не включён в приложение. Переход между прогонами ON/PREFER выполнялся с новой Activity/процессом.

### Найденный и исправленный дефект TrueHD

До исправления стерео TrueHD инициализировался, но не давал ни одного аудиобуфера; native журнал показывал Invalid data в avcodec_send_packet. Это воспроизведение [известной проблемы Media3 #1843](https://github.com/androidx/media/issues/1843), а не подтверждённая порча фикстуры. Сохранены исходный журнал `truehd-before-fix.log` и прежний APK.

Трековый `truehd-layout.patch` задаёт известные положительные sample rate/схему каналов и сохраняет их при пересоздании контекста на seek. Исторический workaround пересоздания сохранён; удаление его вслепую не использовалось. Patch применяется к свежей рабочей копии после проверки исходного SHA256, включён в assets/licenses и описан в NOTICE. После исправления стерео и 5.1 проверены повторно на телефоне.

### Пауза, перемотка, смена дорожек

`check-codec-controls.ps1` ждёт подтверждённого аудиовыхода перед командами и проверяет фактическую позицию, а не только факт отправки intent. Первичная версия драйвера отправляла команды слишком рано; её вывод сам по себе не считался подтверждением seek и заменён полноценным повторным прогоном.

- TrueHD stereo: подтверждён переход на 10000+ мс; на паузе 10531 → 10531 мс; назад на 3000 мс, затем play и продвижение аудио. PASS без нативных ошибок.
- TrueHD 5.1: переход на 10000+ мс; на паузе 10502 → 10502 мс; назад на 3000 мс, затем play и продвижение. PASS.
- Смешанный MKV: AAC → AC3 → DTS → TrueHD → AAC, после каждого выбора проверены ожидаемый активный декодер и дальнейшее продвижение аудио. PASS.

Подробности — `controls-truehd.log`, `controls-truehd-surround.log`, `controls-mixed.log`. Применялся debug probe с production renderers factory; UI выбора дорожек и production custom text selector этим прогоном не принимались (индексы двух текстовых слоёв проверены unit-тестом).

## Ограничения

ТВ, слышимость/качество, A/V-синхронизация, нагрузка при длительном просмотре, D-pad меню восстановления после реального codec error ещё не приняты. EAC3 включён, но отдельной фикстурой не проверялся; DTS-HD/Atmos и прочие канальные схемы не заявляются по этим файлам. Логи и работа debug probe не закрывают эти пункты. Живые каталоги/OpenSubtitles в этой задаче не использовались.
