# Личный список, облако и уведомления: дизайн

Дата: 2026-11-07. Статус: черновик, ждёт подтверждения пользователя.

## Зачем

У пользователя есть шорткаты iPhone ([`F:\projects\shortcuts\movies`](../../../../shortcuts/movies/README.md)) с личным списком фильмов и сериалов в Data Jar: статусы, оценки, рекомендации, проверка новых сезонов. Список живёт только на iPhone; приложение на ТВ о нём не знает, а просмотр на ТВ не попадает в список.

Нужно одно общее состояние для ТВ и iPhone (позже — PWA): что смотреть, что смотрю, что посмотрел, оценки, просмотренные серии; уведомления о выходе серий и фильмов в Telegram; рекомендации на ТВ.

Успех: на ТВ добавил фильм «К просмотру» — на следующий день он виден на iPhone; досмотрел серию на ТВ — галочка в облаке и «S2E5» на iPhone; вышла новая серия сериала с включённым «Уведомлять» — сообщение в группе Telegram.

## Цели

- Главная база — Cloudflare D1 за воркером пользователя; API общий для всех платформ (REST + JSON).
- ТВ: «К просмотру», «Просмотренные», «Для вас», статусы и оценки, флаг «Уведомлять», галочки серий, карточки «Скоро».
- Cron в воркере: проверка новинок, сообщения в Telegram, ежедневная копия в Google-таблицу.
- iPhone: шорткаты переезжают в этот репозиторий; Data Jar — локальная копия с синхронизацией.

## Не цели

- Аккаунты и раздельные списки на человека (один общий список; вернуться при PWA).
- PWA сейчас.
- ИИ-рекомендации на ТВ и в воркере.
- Перенос текущего Data Jar в облако (пользователь его не наполнял; облако наполняется историей ТВ при первом запуске).
- Push-уведомления на ТВ.

## Антицели

- Поведение просмотра, поиска раздач, плеера, субтитров и «Продолжить» для фильмов и сериалов не ломается.
- ТВ и iPhone работают без сети к воркеру: правки копятся и уходят позже; отсутствие облака не блокирует просмотр.
- Секреты (ключ воркера, токен бота, доступ к Google) не попадают в код, документацию, журналы.
- Сообщения в Telegram не дублируются: одно событие — одно сообщение.

## Решения пользователя

### Хранилище и синхронизация

- Главная база — Cloudflare D1, доступ только через воркер. Запросы — с ключом доступа (как `X-VG-Key` у прокси). Один общий список.
- Конфликт правок: вся запись берётся из самой свежей правки (last-write-wins по записи, по времени правки).
- Google-таблица — только резервная копия, пишет её Cron.
- На ТВ синхронизацией занимается отдельный сервис в фоне (не UI-поток, не экран).
- Первый запуск на ТВ: сначала локальная история и позиции ТВ отправляются на сервер (досмотренное → `watched`, начатое → `watching`), потом список подгружается с сервера.
- Места остановки («Продолжить просмотр») синхронизируются между устройствами, как статусы и серии.
- Синхронизация включается и выключается в настройках: на ТВ — переключатель в «Настройках», на iPhone — флаг в `movies.settings`. Выключена → ни одного запроса к воркеру; список работает локально.

### Статусы

Статусы и поля записи — как в [`data.md`](../../../../shortcuts/movies/data.md) (`unwatched`, `watching`, `watched`, `dropped`, `dismissed`; `my_rating` 1–10; ключ записи `imdb_id` → `kp-<id>`).

- «К просмотру» (из карточки или контекстного меню) → запись со статусом `unwatched`.
- Начал смотреть что угодно → `watching`; если тайтла не было в списке — добавляется сам.
- Фильм → `watched`: при оценке (экран окончания, если досмотрено ≥ 90 %, или контекстное меню) или при досмотре ≥ 90 % без оценки. Без оценки — в статистике и рекомендациях по вкусу не учитывается.
- Сериал → `watched` после последней серии последнего сезона.
- Оценка сериала: предлагается после последней серии вышедшего сезона; одна оценка на сериал, перезаписывается.

### Флаг «Уведомлять» (`notify`)

- Только у сериалов. Включается автоматически при первом просмотре; выключается и включается вручную — в карточке на ТВ и в Movie Card на iPhone.

### Главная на ТВ

- «Продолжить просмотр» — ряд в каждом разделе («Все», «Фильмы», «Сериалы»), по типу раздела.
- «К просмотру» (только `unwatched`), «Просмотренные» (`watched`, оценка на карточке), «Для вас» — отдельные пункты левого меню.
- В «Все» — ряды «Похожие на „X“».

### Серии

- Серия, досмотренная ≥ 90 %, получает галочку в карточке сериала и пишется в облако.
- Ручная отметка серии и сезона целиком (контекстное меню на серии).
- В Movie Card на iPhone — на какой серии остановился («S2E5»).

### «Скоро» (ещё не вышло)

- Признак — как в `data.md`: `premiere_date` > сегодня; нет даты → `year` > текущего.
- Метка на постере «Скоро · 12 мар 2027».
- В карточке вместо «▶ Смотреть» — «К просмотру» и «Уведомлять»; раздачи не ищутся.
- Невышедшие серии — серые с датой, недоступны.

### Рекомендации «Для вас»

- Похожие по оценкам: тайтлы с оценкой ≥ 8 → «похожие» из каталога (TMDB / poiskkino) → без тех, что уже в списке.

### Telegram

- Новый бот (@BotFather), сообщения в общую группу.
- События: новая серия вышла; объявлен новый сезон (с датой); фильм из списка вышел; напоминание за день до серии или премьеры; сериал завершён или закрыт.
- Пропускать тайтлы со статусом `dropped`. Сериалы — только с включённым `notify`.
- Статус «завершён/закрыт» — из TMDB (`Ended` / `Canceled`), т. к. poiskkino статус не отдаёт.

### iPhone

- Шорткаты переезжают в этот репозиторий; сборка их `build.sh` на Mac, проверка пользователем на iPhone.
- Синхронизация не чаще раза в день и только при обращении к данным: шорткат сверяет дату последней синхронизации (хранится в Data Jar); если не сегодня — забирает изменения.
- Правки сразу уходят в облако; без сети копятся в очереди в Data Jar и уходят при следующей удачной связи.

## Порядок этапов

Каждый этап — отдельный план и отдельная проверка.

1. Облако: D1 и API в воркере (тайтлы, серии, синхронизация).
2. ТВ, список: фоновая синхронизация (первичная выгрузка истории ТВ, позиции), «К просмотру», «Просмотренные», контекстное меню, статусы и оценка, «Уведомлять», галочки серий.
3. ТВ, «Скоро».
4. ТВ, «Для вас».
5. Cron: новинки, Telegram, копия в Google-таблицу.
6. iPhone: перенос шорткатов, синхронизация, очередь правок.

## Ограничения

- Android: Kotlin, Compose for TV, пакет `dev.gamspi.videogallery`; сборка только через Docker; ABI `armeabi-v7a`; требования [AGENTS.md](../../../AGENTS.md).
- Воркер — [`proxy/cloudflare-worker/worker.js`](../../../proxy/cloudflare-worker/worker.js); сейчас пользователь развёртывает его через дашборд. Бесплатный тариф Cloudflare (лимиты D1, Cron, Queues сверить с документацией при планировании).
- poiskkino демо-ключ — 200 запросов в сутки.
- У TMDB id фильма и сериала пересекаются: тип — часть ключа везде, где хранится id (как в [спеке сериалов](2026-11-07-series-design.md)).
- Ключи воркера, бота, Google — через `SecretStore` / `.env` на ТВ и секреты Cloudflare в воркере.

## Решения, оставленные строителю

Мой выбор, пользователь детали не обсуждал:

- Контекстное меню на ТВ — долгое OK на карточке: «К просмотру», «Оценить», «Смотрел», «Уведомлять», «Бросил», «Не предлагать», «Убрать из списка» (пункты решены пользователем, способ вызова — мой выбор). Удаление из списка синхронизируется (метка удаления, а не стирание строки).
- В D1 хранится запись целиком: пользовательские поля и метаданные (название, постер, тип, даты, жанры, `release_status`, `next_episode`), чтобы ТВ, iPhone и Cron не ходили в каталоги лишний раз. Метаданные заполняет тот, кто добавил запись; Cron обновляет поля сериалов.
- Ключ записи — по `data.md`: `imdb_id` → `kp-<id>`; нет обоих → `tmdb-<тип>-<id>`. Записи `ai-…` Cron не проверяет.
- Серии и позиции — отдельные таблицы, у каждой строки своё время правки: правка тайтла не затирает галочки и позиции.
- Источник дат для Cron — TMDB; poiskkino только для записей, у которых есть лишь id Кинопоиска (лимит 200/сутки).
- ТВ подтягивает изменения при запуске и при открытии разделов списка; правки отправляет сразу, без сети — из очереди.
- `watching` ставится, когда реально пошло воспроизведение. Новый сезон у `watched`-сериала → `watching` (как в `data.md`).
- При выключенной синхронизации правки продолжают копиться в очереди и уходят после включения.
- Сервер не отвечает при включённой синхронизации → паузы между попытками растут (например 1 мин → 5 → 30 → 2 ч), без потока повторов; в настройках видно «Сервер недоступен с …».
- Отдельный ключ доступа к API списка, не ключ прокси. id группы и токен бота — секреты воркера.
- Google-таблица: раз в сутки полная перезапись, листы «Тайтлы» и «Серии».
- Связь каталогов: по `imdb_id`, иначе по id Кинопоиска; для TMDB IMDb-id из `external_ids`. Записи без обоих — ключ по правилам `data.md`.
- Схема D1, формат API, механизм выдачи изменений «с момента X», хранение времени правки.
- Локальный кеш списка на ТВ, очередь неотправленных правок, механизм фонового сервиса (например WorkManager).
- Время запуска Cron и время отправки напоминаний.
- Как Cron помнит отправленные события (чтобы не дублировать).
- Развёртывание воркера: дашборд или `wrangler`.
- Место шорткатов в репозитории (например `ios/shortcuts/`).

## Проверка

- Unit-тесты: слияние правок по свежести, переходы статусов, признак «Скоро», подбор «Для вас», очередь офлайн-правок.
- Воркер: тесты API и Cron (локально `wrangler dev` или аналог).
- ТВ: сценарии пультом по каждому этапу, запись в протокол приёмки.
- Telegram: тестовое событие в группе.
- iPhone: сценарии шорткатов у пользователя.
