# Этап 6: iPhone — перенос шорткатов, синхронизация, очередь правок

> **For agentic workers:** шаги с чекбоксами (`- [ ]`). Сборку на Mac и проверку на iPhone отмечает только тот, кто их реально выполнил.

Дата: 2026-11-11. Статус: XML и документация готовы в рабочем дереве на базе `2193f25`; на Mac не собиралось, на iPhone не проверялось.

**Goal:** шорткаты iPhone (Data Jar) работают с тем же облаком списка, что ТВ: правки уходят сразу, без сети копятся в очереди, изменения с ТВ приходят раз в день при обращении к данным; в карточке сериала видно, на какой серии остановился.

**Architecture:** новый суб-шорткат [Movie Sync](../../../ios/shortcuts/sync/README.md) — единственное место, где шорткаты ходят в воркер `cloud/list-worker` (`POST /v1/batch`, `GET /v1/changes`, заголовок `X-VG-List-Key`). Остальные шорткаты зовут его через Run Shortcut по имени: `auto` в начале, `{key}` после правки, `now` из меню Rate. Состояние синхронизации — в `movies.sync` (дата, курсор, очередь по ключу), отметки серий — в `movies.episodes`. Схема полей и сопоставление — [data.md](../../../ios/shortcuts/data.md#синхронизация-с-облаком).

**Spec:** [дизайн](../specs/2026-11-07-watchlist-sync-design.md), разделы «iPhone», «Хранилище и синхронизация», «Статусы», этап 6. Облако — [план этапа 1](2026-11-07-list-cloud.md), Cron — [план этапа 5](2026-11-10-cron-telegram.md).

## Решения пользователя

1. Забор изменений не чаще раза в день и только при обращении к данным: Movie Sync в начале Rate, Recommend, Stats, Card, Add; дата последней синхронизации — в Data Jar (`movies.sync.last_date`). Ручной пункт «Синхронизировать» в меню Movie Rate. Флаг и доступ — `movies.settings.sync_enabled`, `sync_url`, `sync_key` (ключ вписывает пользователь, в репозитории его нет). Выключено → ни одного запроса.
2. Каждая правка (статус, оценка, оценки сезонов — если есть, `notify`, заметка, теги, удаление) сразу уходит в облако; без сети — в очередь `movies.sync.queue`, которая уходит при следующей удачной связи (в начале Movie Sync и перед каждой отправкой). Время правки клиента — для LWW. Забор: LWW по записи, метки удаления, курсор `seq` со страницами.
3. Серии: достаточно для «Остановился: S2E5» в Movie Card. Позиции на iPhone не нужны.
4. Movie Seasons удаляется (его заменяют Cron воркера и Telegram): папка, таблицы, граф, порядок сборки, TESTING, GUIDE, data.md. Поля, которые заполнял только он, помечены.
5. Записи с ТВ могут иметь ключ `tmdb-tv-<id>` / `tmdb-movie-<id>`: шорткаты принимают любой ключ, «Обновить данные» ищет poiskkino по названию и году, ключ не меняется.
6. Ссылки, сломанные переносом в `ios/shortcuts/`, исправить. `movies.seed_keys` и Movie Seed оставить.

## Решения исполнителя

- **Голос** (Movies): только отправка новой записи, без забора — короче путь Siri. Recommend в голосовом режиме (Dictionary-вход) синхронизацию не зовёт; Movie Tonight получает её через Recommend (`today`).
- **Очередь — словарь по ключу**, а не список: повторная правка тайтла заменяет строку (облаку нужна последняя версия всей записи) и обходит проблему «список из одного элемента ложится не массивом».
- **Тело POST — текст JSON**, собранный из строк очереди (`Text [Repeat Item]` → Combine `,`), Request Body = File: воркер требует массив `titles`.
- **Время правки** — `updated_ms` в записи (мс от 1970-01-01 UTC, Get Time Between Dates от `1970-01-01T00:00:00Z`), ставит Movie Sync. В облаке это `updated_at` строки; при приёме записи `updated_ms` = `updated_at`.
- **Без try/catch**: перед запросом — Get Current IP Address (Local); пусто → выход, очередь ждёт. Правка пишется в очередь до запроса, поэтому системная ошибка сети данных не теряет.
- **Выключено**: правки копятся в очереди без запросов и уйдут после включения (как на ТВ).
- **Movie Card**: пункт «Уведомления: вкл / выкл» для сериалов (флаг `notify` общий с ТВ и Cron); строка «Остановился: S2E5» — максимум из `movies.episodes.<key>`; отправка после правки — один общий шаг 31a перед «Похожими» (они выходят через Stop and Output), удаление и «Не предлагать» шлют сами перед выходом.
- **Movie Add**: дубль ещё и по `title_ru` + году — записи с ТВ (`tmdb-…`) бывают без `title_en`.
- **Первичной выгрузки** существующего Data Jar нет (не цель спеки): запись попадает в облако при первой правке.
- Поля облака и Data Jar совпадают по именам (сверено с `cloud/list-worker/src/worker.js`, `cron.js`, `app/.../watchlist/*.kt`) — таблица сопоставления в data.md.

## Риски

- Ошибка любого из предположений задачи 11 ломает синхронизацию, но не локальный список: Data Jar пишется до Movie Sync.
- Сервер недоступен при живой сети (DNS, таймаут) → системная ошибка Get Contents of URL закроет вызывающий шорткат; правка уже в очереди.
- Очередь > 500 строк и `ai-`ключ длиннее 80 символов воркер не примет — описано в [Movie Sync](../../../ios/shortcuts/sync/README.md#заметки--ограничения).
