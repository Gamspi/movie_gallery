## Ограничения импорта

WatchHistoryStore хранит максимум 20 незавершённых записей и удаляет досмотренные.
PlaybackStore не хранит метаданные для восстановления тайтла из torrent key.
Поэтому первый импорт переносит лишь доступную историю; ранее удалённые досмотры
не восстанавливаются. Запись нового полного списка начинается после интеграции.
Старые записи без source и IMDb не получают выдуманный id каталога.

## Решение по хранению

На первом шаге используется отдельный сериализованный снимок с атомарной заменой
файла через Android AtomicFile. Под mutex изменения, очередь и курсор коммитятся
вместе; StateFlow публикуется только после успешной записи. Ошибка чтения не
превращается в пустой список с перезаписью данных. Секреты в снимок не входят.
Дисковый адаптер и доменные операции проверяются отдельно.

Компоненты задачи 2: ListSync выгружает снимок очереди пачками до 50 строк и читает страницы по 100; ListSyncRunner реализует backoff и отмену через enabled StateFlow; подключение описано ниже. [Протокол](../../verification/2026-11-08-tv-watchlist.md).

Подключение задачи 2: ListSyncService — singleton в App, запуск на IO, переключатель и состояние в «Настройки → Сеть», ручной обмен. Адрес/ключ берутся через SecretStore с .env fallback. Импорт — при первом успешном включении, до чтения облака; только доступные записи с известным каталогом или IMDb. События плеера подключены в записи 2026-11-09 ниже. Интерфейс списка — задача 4.

2026-11-09: плеер пишет прогресс в отдельный список раз в 10 секунд и при паузе/выходе через очередь приложения. Данные/очередь тайтла, позиции и отметки серии сохраняются одной транзакцией. Пользовательские поля сохраняются. Позиция из локального облачного снимка читается перед подготовкой видео без ожидания сети; ключи PlaybackStore не меняются. Приёмка на ТВ открыта.
