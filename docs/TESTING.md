# Сборка и проверка

## Автоматические проверки

Все команды запускаются из корня репозитория. На Windows используйте PowerShell-скрипт; в Bash замените `.ps1` на `.sh`.

```powershell
# Полная проверка и APK
./scripts/gradle-docker.ps1 ./gradlew testDebugUnitTest assembleDebug

# Повторный прогон без использования предыдущих результатов задач
./scripts/gradle-docker.ps1 ./gradlew testDebugUnitTest --rerun-tasks

# Выборочная проверка субтитров
./scripts/gradle-docker.ps1 ./gradlew testDebugUnitTest --tests 'dev.gamspi.videogallery.subs.*'
```

Проверьте выходной код и XML в `app/build/test-results/testDebugUnitTest/`; HTML-отчёт — `app/build/reports/tests/testDebugUnitTest/index.html`. `UP-TO-DATE` означает использование предыдущего результата, а не новый запуск теста.

Тесты реальных `Media3 Format/Tracks` и селектора используют Robolectric 4.17 с SDK 34: эти классы обращаются к Android API. Чистые тесты распределения слотов остаются обычными JVM-тестами. SDK 34 выбран явно для JDK 17 Docker-образа; это не изменение targetSdk приложения. При первом запуске Robolectric скачивает Android runtime; он сохраняется в `caches/robolectric` постоянного Gradle home. Настройка: [официальная документация](https://robolectric.org/getting-started/).

Проверенная база `d1ea23e` от 2026-10-31: свежий полный прогон — 242 теста в 32 наборах, ошибок/падений/пропусков нет. Эта цифра — снимок состояния, не неизменяемое требование к будущим тестам.

## Правки документации

- `git diff --check` не должен сообщать об ошибках пробелов.
- Новые/изменённые файлы должны декодироваться как UTF-8 без BOM.
- Локальные Markdown-ссылки должны вести к существующим файлам; при добавлении заголовочных ссылок проверяйте и якоря.
- Статусы сверяйте с кодом, историей и протоколом тестов. Не отмечайте исторический запуск падающих тестов только потому, что сейчас тесты проходят.

Старые планы упоминали `$TEMP/u8.py`; этот временный файл не входит в репозиторий и не является обязательной частью проверки. Не запускайте случайный внешний скрипт с таким именем.

## Что JVM-тесты не подтверждают

- Работу JNI libtorrent4j, DHT и пиров на настоящем устройстве.
- Доступность каталогов, трекеров и OpenSubtitles из сети пользователя.
- Поддержку аудио/видеокодеков и одновременных текстовых рендереров.
- Управление D-pad, экранную клавиатуру, восстановление фокуса и lifecycle на ТВ.

Текущая сборка содержит только `armeabi-v7a`. Перед запуском проверьте `adb -s <device> shell getprop ro.product.cpu.abilist`. Для x86_64-эмулятора нужны соответствующие native-зависимости и конфигурация; не считайте его готовой запасной платформой проверки.

## Приёмка базового приложения на ТВ

Чеклист ниже — шаблон, все пункты изначально не выполнены. Проверяйте на файлах/раздачах, которые можно использовать для тестирования, и записывайте конкретный результат.

- [ ] APK устанавливается поверх прежнего; настройки и позиция сохраняются.
- [ ] Каталог: нет ключа, неверный ключ, корректный ключ, смена источника, ошибка сети и «Повторить».
- [ ] Навигация только пультом: галерея → карточка → Назад восстанавливает фокус; поиск → результат → карточка; переход со строки поиска вниз к результатам.
- [ ] Раздачи: результаты нескольких источников, фильтр качества, отказ одного провайдера, восстановление выбранной строки после возврата.
- [ ] Стример: один файл стартует сразу, несколько дают выбор, отсутствие видео даёт ошибку, отмена метаданных/буфера освобождает сессию.
- [ ] Перемотка в ещё не загруженную часть: приходит Range, нужные куски получают приоритет, фильм продолжает играть.
- [ ] Озвучка, пауза, продолжение после выхода, Home/возврат, повтор после ошибки; удержание стрелок и закрытие меню работают корректно.
- [ ] Статус загрузки виден; после выхода файлы удаляются и новая раздача стартует без вмешательства старой сессии.
- [ ] После G-01: остановка полезной загрузки на 30 секунд показывает предупреждение и позволяет сменить раздачу; пауза не вызывает ложное предупреждение.

## Приёмка хранения торрентов (G-05)

Контракт: [план G-05](superpowers/plans/2026-11-01-torrent-storage.md). Используйте небольшую тестовую раздачу; настройки хранения сохраняются сразу.

- [ ] Исходный режим — «удалять»; после выхода нативная сессия остановлена, каталог удалён.
- [ ] Включить «хранить», открыть файл, выйти. После перезапуска приложения сохранённые данные остаются; повторный magnet использует тот же каталог и проверяет куски. Наличие файлов само по себе не доказывает повторное использование движком.
- [ ] После выхода убедиться в отсутствии активной раздачи и отдачи. Проверить выход во время метаданных, буфера и воспроизведения.
- [ ] Очистить кэш во время активного просмотра: активный каталог и воспроизведение сохранены; неактивные записи удалены.
- [ ] Уменьшить лимит и запустить новую раздачу: старейшие неактивные записи вытесняются; активная не удаляется. Файл больше лимита даёт понятную причину.
- [ ] Нехватка места до старта и во время просмотра: понятная ошибка и выход к раздачам. Не заполнять пользовательское хранилище ради проверки; управляемый тестовый источник места в unit-тестах проверяет логику, а не JNI.
- [ ] Быстро выйти и снова открыть тот же hash; старая очистка не удаляет новый просмотр. Повторить со сменой hash.
- [ ] Пультом проверить режим, обе кнопки лимита, очистку, фокус и Назад. Телефонный smoke учитывать отдельно от ТВ.

## Приёмка двойных субтитров

Для эксперимента задачи 5 добавлена debug-only Activity. Запуск, ограничения и фактические результаты: [протокол](verification/2026-10-31-dual-text-probe.md). Пользователь выбрал телефон для проверки рендереров; приёмка пульта и основного интерфейса остаётся проверкой на ТВ.

В рабочем дереве на базе `b5f4833` интеграция задач 5–7 реализована. Gate двух рендереров и вывод обоих слоёв основным PlayerScreen подтверждены на телефоне. Чеклист ниже относится к полной приёмке на целевом ТВ и живом OpenSubtitles; результаты телефона не закрывают его автоматически.

- [ ] MKV с двумя известными текстовыми дорожками en/ru: два независимых слоя, A сверху, B снизу; встроенный `SubtitleView` не дублирует текст.
- [ ] Пауза, seek и возобновление не оставляют устаревшие cue на экране.
- [ ] Меню доступно даже у видео без аудиодорожек; Выкл/включение каждого слоя и переключение встроенный ↔ внешний действуют независимо.
- [ ] Один язык для A и B: одна встроенная дорожка не назначается обоим; второй слой использует внешний источник или сообщает об отсутствии.
- [ ] OpenSubtitles: hash match, fallback IMDb, один отсутствующий язык, отсутствие ключа, неправильный ключ, неверный логин и лимит. Видео продолжает играть при ошибке субтитров.
- [ ] Внешние субтитры: SRT/VTT/ASS, кириллица UTF-8/cp1251, стиль и сдвиг ±500 мс с ограничением ±10 секунд. Проверка парсера cp1251 отдельно не доказывает доступность локального файла через UI.
- [ ] При видимом оверлее плеера текст поднимается над ним; длинные реплики и пустой слой не ломают расположение.
- [ ] Выход и смена источника во время задержанного запроса не оставляют фонового скачивания или поздней записи в состояние.

В плане этапа 3 встречаются конкретные LAN-адреса и имена тестовых контейнеров прежней сессии. Это примеры, а не гарантированно доступная инфраструктура. Перед использованием определите адрес хоста, доступный ТВ, и наличие тестового файла; не останавливайте чужие контейнеры.

## Протокол проверки

Для каждого прогона создавайте Markdown-отчёт в `docs/verification/` (каталог появится с первым фактическим отчётом), используя следующие поля:

```text
Дата:
Commit приложения / наличие локальных изменений:
Команда сборки, результат, число тестов:
Устройство / ABI / Android API:
Тестовые файлы: контейнер, кодеки, языки и типы дорожек:
Сценарий | Ожидание | Факт | PASS / FAIL / NOT RUN
Найденные дефекты и ссылки на задачи:
Ограничения проверки:
```

Не включайте ключи, пароли, bearer-токены или полные URL с секретными параметрами. Если устройство недоступно, запишите `NOT RUN`; не заменяйте проверку на ТВ успешной сборкой.

## Приёмка PoiskKino и кэша (G-04)

Автоматические результаты и ограниченный smoke телефона: [протокол G-04](verification/2026-11-01-poiskkino-cache.md). Тесты не подтверждают доступность живого API.

- [ ] Сохранённый Кинопоиск/TMDB остаётся выбранным после установки обновления; новый выбор по умолчанию — PoiskKino.
- [ ] Нет ключа / неверный ключ / лимит дают понятное сообщение и переход в настройки.
- [ ] С корректным ключом PoiskKino работают популярное, жанры, поиск «матрица», карточка с IMDb и переход к раздачам.
- [ ] Повторное открытие в пределах TTL использует кэш; после смены ключа/источника нет чужой или прежней ошибочной выдачи.
- [ ] Физический пульт: начальный фокус, три кнопки источника, вход/выход из полей, Back без сохранения, сохранение и возврат в галерею.

Для ограниченного debug-smoke на телефоне с MIUI есть `.settings.SettingsProbeActivity`: она показывает настоящий экран и принимает `--ei keyCode <код>` (19/20/21/22/23/4). Это локальные события окна, не обход системных разрешений ввода в другие приложения. Не сохраняйте снимки настроек с видимыми секретами и не передавайте ключ через adb intent. Вводите реальный ключ на устройстве через настройки/SecretStore.
