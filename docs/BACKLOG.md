# Пробелы и задачи на исправление

Дата: 2026-10-31. База аудита: `d1ea23e`. Все задачи ниже открыты. P1 — мешает надёжному просмотру или завершению этапа 3; P2 — отложенная возможность или технический долг. Приоритеты и предложенные решения — рабочая рекомендация, а не утверждение о ранее согласованном поведении.

Задачи 5–8 двойных субтитров уже описаны в [плане этапа 3](superpowers/plans/2026-10-31-stage3-dual-subtitles.md). Этот документ дополняет его и фиксирует пробелы, у которых не было достаточного плана исправления.

## G-01 · P1 · Реакция на остановившуюся загрузку

**Состояние:** открыто. Спека требует реакции после 30 секунд отсутствия сидов или недостаточной скорости. В `StreamManager` есть 60-секундный таймаут метаданных; цикл `buffer()` после получения метаданных не ограничен по отсутствию прогресса. Пользователь может бесконечно видеть буферизацию.

**Файлы:** `stream/StreamManager.kt`, `StreamScreen.kt`, при необходимости `StreamFormat.kt` и `player/PlayerOverlay.kt`; `StreamManagerTest.kt`.

**План исправления:**

- [ ] Определить сигнал остановки загрузки: отсутствие новых нужных кусков, скорость и число пиров. Числовой порог «низкой скорости» в спеке не задан; записать выбранное значение и обоснование до реализации.
- [ ] Отсчитывать 30 секунд непрерывного отсутствия полезного прогресса монотонными часами; сбрасывать таймер при возобновлении загрузки.
- [ ] Показывать скорость и действие «Выбрать другую раздачу». Предлагаемое поведение — предупреждение с возможностью продолжить ожидание, без автоматического обрыва играющего видео.
- [ ] Различать ожидание метаданных, стартовую буферизацию и остановку загрузки во время просмотра. Пауза и достаточный буфер не должны создавать ложное предупреждение.
- [ ] При уходе к списку раздач остановить принадлежащую экрану сессию и очистить её файлы.

**Готово, когда:** тесты с виртуальным временем покрывают границу 30 секунд, сброс таймера, смену сессии и отсутствие ложного предупреждения при паузе/готовом буфере; на ТВ можно выйти из зависшей загрузки и запустить другую раздачу.

## G-02 · P1 · Отмена HTTP-запросов субтитров

**Состояние:** реализовано в рабочем дереве, unit-проверки прошли. `OpenSubtitlesClient.fetchBytes()` и оба Range-запроса используют `SubtitleHttp.awaitBody()`: отмена вызывает `Call.cancel()` и закрывает ответ даже во время чтения тела. Шесть MockWebServer-тестов покрывают задержанные заголовки/тело; VM-тесты — отмену хэша, поиска, загрузки и поздние ответы при смене выбора. Результаты общего прогона — в STATUS; устройство и живые запросы остаются частью G-09.

**Файлы:** `subs/OpenSubtitlesClient.kt`, `OpenSubtitlesHash.kt`, сетевой helper (существующий пример — `torrents/HttpAwait.kt`); тесты клиента/хэша и будущий `PlayerViewModelTest`.

**План исправления:**

- [x] Связать отмену операции с отменой OkHttp Call, включая чтение тела после получения заголовков; закрывать Response во всех ветках.
- [x] Сохранить распространение `CancellationException`, не превращать отмену в `Failed` или `null`.
- [x] При смене источника слоя отменять старую загрузку; поздний ответ не должен подменять новый выбор.
- [x] При уничтожении VM отменять получение хэша, поиск и скачивание; после отмены не обновлять состояние слоёв.

**Готово, когда:** MockWebServer-тесты задерживают отдельно заголовки и тело, отменяют запрос и подтверждают завершение операции без ожидания сетевого таймаута; нет записи в уничтоженную VM и подмены нового выбора поздним ответом. Проверять и скачивание файла, и оба Range-запроса хэша.

## G-03 · P1 · Явный fallback OpenSubtitles по IMDb

**Состояние:** реализовано в рабочем дереве, mock-тесты прошли. Контрактом владеет `OpenSubtitlesClient.search`: запрос по хэшу без IMDb с `moviehash_match=only`, затем запрос без хэша по IMDb только для отсутствующих языков. При ошибке второго запроса точные совпадения сохраняются, а `Ok.languageNotes` передаёт причину ошибки соответствующему слою. При ошибке первого запроса повтор не выполняется. Живой сервис не проверен.

API сверено 2026-10-31 с [официальным справочником OpenSubtitles](https://ai.opensubtitles.com/api-docs#subtitles): параметры могут ограничивать выдачу, `moviehash_match=only` поддерживается, языки передаются через запятую в алфавитном порядке. Stoplight в этой сессии недоступен; используется официальный справочник того же API v1.

**Файлы:** `subs/OpenSubtitlesClient.kt`, `OpenSubtitlesApi.kt`, будущие `SubtitleSourcing.kt` / `PlayerViewModel.kt`; тесты клиента и слоёв.

**План исправления:**

- [x] Перед изменением сверить семантику сочетания параметров с официальной документацией API и сохранить ссылку/дату проверки.
- [x] Зафиксировать контракт: сначала результаты точного хэша; при отсутствии подходящих результатов нужного языка — поиск по IMDb без ограничения хэшем. Выбрать один слой, отвечающий за fallback, чтобы не дублировать запросы в клиенте и VM.
- [x] Сохранять приоритет hash match, затем downloads; удалять дубли по `fileId` при объединении.
- [x] Не повторять запрос при ошибке ключа/лимите; отсутствие результатов отличать от сетевой ошибки.

**Готово, когда:** есть тесты «хэш не найден → IMDb найден», «хэш дал только en → ru получен по IMDb», «нет IMDb», «нет Range», «нет ключа/лимит» и отмены между запросами. Результат API не должен подразумеваться по одному успешному mock-ответу.

## Наблюдение за техническим долгом

Сборка базы выдаёт предупреждения об устаревших `androidx.security.crypto` API, Gradle API перед переходом на Gradle 10 и delicate coroutine API в `StreamServer`. Сейчас они не ломают сборку. При планировании обновления зависимостей требуется отдельная оценка миграции; массовое обновление версий не входит в исправление функциональных пробелов выше.
