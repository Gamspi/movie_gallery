# Работа с VideoGallery

## Контекст и документы

- Это Kotlin-приложение для Android TV, а не веб-проект. Основной пакет: `dev.gamspi.videogallery`.
- Перед задачей прочитайте [README](README.md), [STATUS](docs/STATUS.md) и относящийся к задаче план. Открытые пробелы перечислены в [BACKLOG](docs/BACKLOG.md).
- Спецификация описывает целевой продукт; STATUS — реализованное и проверенное состояние. Поздние решения в планах могут сужать этап: не выдавайте их за выполненные требования всей спеки.
- Код этапа 3 реализован до задачи 7 включительно. Gate задачи 5 пройден на выбранном пользователем Redmi Note 8 Pro; полная приёмка задачи 8 на ТВ и живом OpenSubtitles ещё не завершена. Актуальные проверки — в STATUS.
- Статусы обновляйте по коду и проверкам. Наличие файла или коммита не доказывает проверку на устройстве; успешный unit-тест не доказывает работу нативного движка.

## Разработка

- Сначала проверьте `git status`; сохраняйте чужие изменения. Не создавайте заново существующий Gradle-проект или Git-репозиторий.
- Держите изменения в рамках задачи. Автоматическое создание коммита или публикация не являются частью обычного редактирования. Не добавляйте вымышленное авторство.
- Общие инструкции здесь заменяют устаревшие требования планов к конкретному агенту, отсутствующим skills и временным скриптам вне репозитория. Делегирование не является обязательным.
- Кодировка текстовых файлов — UTF-8 без BOM. Комментарии к новому коду — кратко на английском, пользовательские строки — на русском.
- Ключи и пароли проходят через `SecretStore`; не помещайте их в код, документацию, фикстуры или журналы. Обычные настройки сейчас также используют этот слой; позиции и предпочтение аудио — отдельный `PlaybackStore`.
- Сетевую и файловую работу не выполняйте на UI-потоке. Не поглощайте `CancellationException`. Отмена операции должна отменять HTTP-запрос и освобождать ответ/сокет, а не только прекращать обновление состояния.
- В `stream` сохраняйте владение сессией: уход старого экрана не должен останавливать новую раздачу. Локальный сервер слушает только `127.0.0.1`.
- UI проверяется пультом: фокус, возврат Назад, удержание стрелок, восстановление выбранной карточки. Не перехватывайте навигацию открытого меню корневым обработчиком.
- Не меняйте ABI молча: текущая цель — ТВ с `armeabi-v7a`. Для другого ABI нужны совместимые JNI-зависимости и отдельная проверка.

## Проверки

- Сборка и тесты выполняются через Docker-скрипты; локальный SDK не требуется. Команды и приёмка: [TESTING](docs/TESTING.md).
- Для кода используйте релевантные unit-тесты; для изменений зависимостей, DI, навигации и UI также `assembleDebug`. Перед завершением этапа — полный набор unit-тестов и сборка.
- Проверяйте XML в `app/build/test-results/testDebugUnitTest/`, а не только код завершения Gradle. Если задача `UP-TO-DATE`, укажите использование прежних результатов; для свежего прогона используйте `--rerun-tasks`.
- Правки только Markdown не требуют сборки Android: проверьте локальные ссылки, кодировку, `git diff --check` и соответствие фактам.
- Не отмечайте сценарий на ТВ выполненным без результата. Записывайте commit, модель/ABI/API устройства, сценарий, итог и ограничения проверки без секретов.
- При завершении задачи синхронизируйте STATUS, соответствующий пункт BACKLOG и статус плана. Исторические шаги «тест сначала упал» не отмечайте без подтверждения.
